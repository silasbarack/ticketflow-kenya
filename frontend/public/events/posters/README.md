# Event poster artwork

Real, photographic poster images for TicketFlow Kenya events. **One file per event,
named after the event's slug.**

```
public/events/posters/<event-slug>.webp
```

Nothing in this folder is generated by the application. Posters are raster image
files that get dropped in here; the app only ever reads them.

## Current state

Four events have real photographs, sourced from Wikimedia Commons under CC BY-SA
by `scripts/source-event-photos.py` (attribution in `CREDITS.md`, which must be
preserved if these images are redistributed):

- `kisumu-lakeside-cultural-festival-2026` — traditional dancers
- `mombasa-spice-and-seafood-festival-2026` — grilled seafood
- `jamhuri-family-carnival-2026` — funfair ferris wheel
- `nairobi-digital-economy-summit-2026` — conference auditorium

The other six have **no poster** and render a neutral "Poster unavailable"
state. Commons has no usable free photography for them: searches returned
subjects that were wrong (a doorway in Crete for a Nakuru student festival, a
1901 newspaper graphic for a road race) or carried other events' branding
(a "BLACKPINK" LED wall, a "Pattaya Bike Week" stage), which must never appear
on a TicketFlow listing. They need generated artwork — see below.

## Generating the posters

```bash
cd frontend
export OPENAI_API_KEY=...                      # or STABILITY_API_KEY / REPLICATE_API_TOKEN
python scripts/generate-event-posters.py       # only the posters that are missing
python scripts/generate-event-posters.py --force            # redo all of them
python scripts/generate-event-posters.py kulture-iii-2026   # just one event
```

The script reads each event's art direction from `backend/prisma/poster-art.json`,
renders it through whichever provider has a key set, then centre-crops, resizes
and encodes a WebP inside the size budget below. With no key set it prints what is
missing and exits without writing anything — it never falls back to locally drawn
substitute artwork.

## Adding or replacing a poster

1. Drop the file in as `<event-slug>.webp` — the slug is the `slug` column on the
   event (e.g. `kulture-iii-2026.webp`).
2. That's it. No component changes: `EventCard` and the event detail page both
   render `components/EventPoster.tsx`, which reads `event.posterUrl` from the
   API. The seed already sets `posterUrl` to `/events/posters/<slug>.webp`.

If a file is missing, the card shows a neutral "Poster unavailable" state and logs
the failing URL to the console in development. That state is an error indicator —
it is never artwork, and must not ship as one.

## Image requirements

| Property | Value |
| --- | --- |
| Format | WebP preferred (JPEG/PNG accepted) |
| Orientation | Landscape |
| Source size | 1600×1200, 1536×1024, or similar high-resolution landscape |
| Optimised weight | 150 KB – 500 KB |
| Crop | Rendered with `object-fit: cover` — 4:3 on cards, 16:10 on the detail page. Keep the subject near the centre; the card darkens its lower third for the title overlay. |

## What belongs in the image

The image is **marketing photography only**. The card already renders the event
title, date, countdown, venue, ticket tiers, trust row and Book Now button as live
HTML, so the artwork must not duplicate them:

- **No** ticket price tables — prices change, images don't.
- **No** burned-in title/date/venue text, and no "sample"/"demo"/"placeholder"
  stamps. Demo status is a data flag (`isDemo` / `organizerVerified` /
  `salesEnabled`) surfaced as a small UI badge outside the artwork.
- **No** invented sponsor, brand, artist or venue logos, and nothing implying a
  partnership or endorsement that does not exist.
- For fictional or demo events, use generic photographic event scenes. Do not
  present a generated image as a photograph of a real event, a real performer, or
  a specific real venue.
- For a real event, use the organizer's own authorised artwork.

## Art direction

Each event carries a `posterPrompt` in `backend/prisma/seed.ts` describing the
photograph it should have. That field is **development-only**: it is not a Prisma
column, is never written to the database, and is never sent to the browser.
